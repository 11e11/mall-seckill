# 秒杀库存流水改造

## 背景与范围

Redis Lua 负责秒杀入口削峰和库存预扣，MySQL 的 `shop_seckill_sku` 仍是活动库存最终依据。本次在既有 `shop_inventory_flow` 中补充秒杀活动库存流水，不记录 Redis 预扣，也不改变订单状态机和 MQ 链路。

## 核心设计

- `inventory_type` 区分 `PRODUCT` 与 `SECKILL`，历史记录默认归为 `PRODUCT`。
- `activity_id`、`activity_sku_id` 用于按活动 SKU 审计和对账。
- 冻结、确认、释放分别使用 `SECKILL_FREEZE`、`SECKILL_CONFIRM`、`SECKILL_RELEASE` 前缀生成唯一 `flow_key`。
- 流水写入与活动库存更新处于同一本地事务；支付与关单仍先通过 `inventory_status` 条件更新竞争，胜出方才更新库存并写流水。

## 一致性与运维检查

- 冻结：`available_stock` 减少、`locked_stock` 增加。
- 确认：`locked_stock` 减少、`sold_stock` 增加。
- 释放：`locked_stock` 减少、`available_stock` 增加。
- 按 `biz_id` 检查订单流水，按 `(inventory_type, activity_sku_id, change_type)` 汇总活动库存变化。
- 已有数据库先执行 `db-init/inventory_stock_seckill_flow_upgrade.sql`，新环境使用更新后的初始化 SQL。

## 非目标

本次不记录 Redis 入口预扣流水，不执行压测，也不调整普通商品库存逻辑。
